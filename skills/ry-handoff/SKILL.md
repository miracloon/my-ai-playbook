将当前对话的有效信息打包为交接文档，供新 agent 接力继续任务。

将接手的 AI 视为**极度聪明但刚入职的同事**——不解释基础概念，但必须交代项目状态、决策脉络和当前意图。每条信息都应有存在理由：新 agent 不知道就会犯错的，写；没有这种风险的，不写。

默认按同环境交接处理。环境模式由用户提供或暗示；用户未明确要求跨环境、导出、复制到其他平台时，不主动判断或确认环境。

## 同环境交接（默认）

新 agent 在同一工作环境中接手，拥有完整文件系统访问权限。

- **引用优先**——文档、代码、配置、commit 用路径引用，不复述内容
- **补全文件中不存在的洞察**——决策原因、被否定的方案、用户偏好、隐含意图
- **语态**——AI-to-AI，直接陈述事实和任务

输出保存到 `temp/handoff/handoff-{主题}.md`。

建议结构（按需裁剪，不填充空段落）：

- 任务目标（一句话）
- 关键文件（路径 + 角色说明）
- 当前状态（做到哪了、什么能用、什么还没做）
- 决策记录（已确定的方案、否定的方案及原因）
- 注意事项（坑、约束、用户偏好）

## 跨环境导出

新 agent 在全新环境（不同对话、不同平台），无法访问当前文件系统或对话历史。

- **完全自包含**——所有必要信息内联，不依赖外部引用
- **以用户视角撰写**——新 AI 读到后应理解为用户在交代任务
- **代码与配置**——任务继续所必需的直接内联，否则只描述功能和状态

输出保存到 `temp/handoff/handoff-export-{主题}.md`，可直接复制粘贴到新对话首条消息。

## 共通规则

- **省略噪声**——无关讨论、中间试错、已替代的方案细节不保留
- **涵盖**：任务目标、当前状态、已确定的决策及原因、约束和注意事项
