# Capability Analysis

能力阻塞推演的方法和目标。

## 目标

让用户在 agent 创建前看清每条核心能力的实现链路：需要什么准备、什么工具、什么途径，以及阻塞点的解法。

重点是**链路的通透性**——确认"有解"或找到最优解。具体实现可以在目标 agent 创建后与其协作完成，不在本阶段陷入细节。

## 推演内容

对阶段1中识别的每条有讨论价值的能力，代入任务场景做可行性推演。推演可能涉及：

- **现有 skill 匹配**：是否有现成的hermes内置 skill 能解决这个问题，或解决其中一部分
- **权限与能力依赖**：完成这条能力需要什么权限、工具或外部条件
- **阻塞与限制**：可能遇到什么限制（登录、平台限制、格式兼容等），以及可行的解法
- **用户思路验证**：用户提到的工具、方案或偏好是否能解决问题，是否是最优路径
- **Skill 规划**：是否值得为目标 agent 创建专门的 skill 来将某个流程固化
- **替代路径**：如果首选方案有硬阻塞，是否有可接受的替代方案

## 讨论边界

- 只讨论有核心讨论价值的能力——有实际阻塞或需要用户决策的
- 无阻塞、方案明确的能力直接跳过
- 保持在"链路是否通"的层面，不展开具体实现步骤
- 可以灵活使用内置 skill（搜索、查文档等）辅助推演
- 目标是让用户确认"这条路走得通"，而不是现场把路走完

## 产出

推演成果写入 `decisions.md` 的阻塞推演方案部分。不一定进入最终产物。

推演完成后，呈现实现策略流程图，用户认可后继续。
