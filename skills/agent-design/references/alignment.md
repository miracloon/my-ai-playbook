# Alignment

设计 agent 时，先理解用户怎么使用它，再把场景翻译成架构决策。

## 意图对齐

先确认用户的原始想法没有被误读。

需要回答：

- 用户想要什么。
- 为什么现在需要这个 agent。
- 用户已经明确了什么，哪些只是模糊直觉。
- 当前输入里有哪些歧义、缺口或隐含期待。
- 这次是新建 profile、重塑已有 profile，还是局部调整。

意图对齐不要求补齐全部设计字段。它只负责确认方向正确。

## 画像完善

方向正确后，围绕目标 agent 逐项补全画像：

| 话题 | 要回答的问题 |
|------|--------------|
| 使用场景 | 什么时候用，怎么发起，期望什么体验 |
| 定位 | 这个 agent 是什么角色，用户为什么会找它 |
| 能力范围 | 做什么，不做什么 |
| 生态关系 | 和核心主管、同驻地其他 profile、用户直接入口的关系 |
| 表达与人格 | 是否需要特定沟通风格、人设或表达边界 |
| 工作流程 | agent 接到任务后如何推进，是否涉及定时、常驻、委派或外部入口 |
| 成功标准 | 什么状态说明这个 agent 设计对了 |

画像完善可以多轮讨论。不要把所有话题塞进一次提问。

如果用户目标是修改已有 profile，先判断影响范围，再只讨论受影响部分：

| 变化 | 可能影响 |
|------|----------|
| 身份 / 定位变化 | SOUL 的角色、职责和生态关系 |
| 能力 / 边界变化 | SOUL、toolset、skill、workspace 规则 |
| 表达方式变化 | SOUL 的表达基线 |
| 工作流程变化 | SOUL、workspace AGENTS、skill、cron、gateway 或外部入口 |
| skill / 权限 / 配置变化 | 落地清单和 `hermes-operations` 操作范围 |

## 交互方式

- 用场景语言和用户讨论，不要求用户直接回答架构术语。
- 用户信息丰富且方向明确时，加速整理。
- 用户信息稀疏或犹豫时，放慢并追问关键分歧。
- 每轮只处理少数真正影响方向的问题。
- 不用审问式清单，不为了完整而补齐低价值字段。

## 收敛标准

进入编译前，设计稿应足以回答：

- 目标 profile 是谁，属于哪个驻地。
- 用户会在什么场景使用它。
- 它做什么，不做什么。
- 它与本驻地其他 profile 的关系。
- 它需要什么表达方式和工作流程。
- 还有哪些未决问题会影响 SOUL、workspace、skill、权限或落地配置。

如果这些信息不足以写出方向稳定的设计稿，继续对齐。
