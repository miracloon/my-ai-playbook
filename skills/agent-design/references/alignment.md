# Alignment

深度对齐的引导、话题覆盖和收敛标准。

## 初步对齐

先确认用户的原始想法没有被误读。

需要回答：

- 用户想要什么
- 为什么现在需要这个 agent
- 用户已经明确了什么，哪些只是模糊直觉
- 当前输入里有哪些歧义、缺口或隐含期待

初步对齐不要求补齐全部设计字段。只负责确认方向正确。

## 深度对齐

方向正确后，逐项讨论 agent 的骨架。

### 核心原则

**已讨论 ≠ 仅覆盖**。每个骨架话题必须真正讨论清楚——用户和核心主管对该话题的理解一致、结论明确，才算"已讨论"。仅仅提到过、问过一遍不算。

### 骨架话题

维持一个内部清单，确保以下话题都被充分讨论：

| 话题 | 要回答的问题 |
|------|-------------|
| 定位 | 这个 agent 是什么角色，用户为什么会找它 |
| 功能 | 能帮用户完成哪些任务 |
| 能力 | 具备哪些手段完成任务（不展开实现细节） |
| 功能边界 | 不做什么 |
| 工作流程路由 | 接到任务后的主干路径和分支 |

功能和能力的区分：

| 概念 | 面向 | 例子 |
|------|------|------|
| 功能 | 用户视角：agent 帮用户做什么 | 帮用户导读视频、速读材料 |
| 能力 | 技术视角：agent 靠什么手段做到 | 下载视频并解析字幕、抓取并清洗网页 |

功能决定定位，能力决定可行性边界。功能清单后续写入产物；能力清单喂给阶段2的阻塞推演。

### 辅助话题

以下话题在骨架讨论中自然浮现，不强制单独展开：

- 使用场景 / 场景推演
- 端点（输入输出、触发方式）
- 生态关系（和同驻地其他 profile 的分工）
- 表达与人格（默认跳过，用户需要时展开）

### 交互方式

- 用场景语言和用户讨论，不要求用户回答架构术语
- 用户信息丰富且方向明确时，加速整理
- 用户信息稀疏或犹豫时，放慢并追问关键分歧
- 每轮只处理少数真正影响方向的问题
- 不用审问式清单，不为了完整而补齐低价值字段

### 收敛标准

骨架话题全部充分讨论后，呈现功能骨架流程图，展示 agent 的功能路径和分支。

用户认可流程图，即可进入阶段2。
