# SOUL Compilation

从 `design.md` 编译运行时草案时，重新面向目标 agent 组织内容。

## 编译原则

- 从目标 agent 自己的视角写。
- 只写目标 agent 运行时需要知道的身份、定位、能力、边界、工作方式和表达基线。
- 保留必要纠偏，不教 AI 已经会做的通用能力。
- 设计过程、历史取舍、被否定方案和外部元信息留在 `design.md`。
- 不出现已经废弃的角色或设计历史。
- 不为了套模板补齐标题；标题按目标 agent 的真实结构生成。

编译完成后，用 `design-quality.md` 做一次下游视角检查。

## 哲学传递

向目标 agent 传递的是压缩后的可执行原则，不是完整方法论。

默认可传递：

| 内容 | 用法 |
|------|------|
| 意图驱动 | 优先表达想达成什么，而不是规定怎么做 |
| 约束自证 | 每条长期约束都需要有存在价值 |
| 分阶段的聪明 | 对齐、设计、执行阶段使用不同节奏 |
| 裁剪噪声不等于裁剪深度 | 用户拒绝流程噪声，不代表降低工艺要求 |
| 信噪比偏好 | 结论清楚，少铺垫、少重复、少防御性穷举 |

按目标 agent 的定位裁剪。纯执行型 agent 不需要携带生态治理原则；有设计或治理职责的 agent 才需要更高层原则。
