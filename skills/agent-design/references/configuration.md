# Configuration

配置对齐用于收敛 profile 落地时需要的少量配置事实。

这一阶段带默认值推进。用户没有反应时，按默认值记录；需要用户明确提供的信息，不猜。

## 对齐方式

- 一轮对话完成，不展开成长期讨论。
- 只处理落地配置，不重新讨论 agent 画像。
- 内置 skill 选拔在前序阶段完成，不放进配置对齐。
- env / credential 不作为默认话题；只有目标功能确实需要时，记录为未决外部依赖。

## 默认值

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| gateway 是否常驻 | 是 | 常驻方案默认使用 `systemctl --user` |
| 是否注册别名 | 是 | 按 Hermes 内置说明书 / CLI help 执行 |
| provider / model | 需要用户提供 | 用户未提供时记录为未决，不猜测 |
| 是否同步渠道 | 是 | 设置 provider / model 或选择渠道前，先执行 `/home/ry/.local/bin/custom-provider-sync apply` |
| 是否接入 TG 渠道 | 否 | 用户明确需要时再配置 |
| 是否暴露 server API | 否 | 用户明确需要时再配置 |

## 写入设计稿

配置对齐结果写入 `design.md` 的落地配置项。运行时草案只保留目标 agent 需要知道的身份、边界和工作方式，不写平台配置细节。
