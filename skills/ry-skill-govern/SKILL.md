# Skill 治理

把用户意图和真实使用证据编译成目标 AI 能独立理解、执行和继续维护的 Skill。旧稿是证据，不是默认基线；允许保留、重构或整体替换，选择由当前需要和验证结果决定。

## 确定当前任务

先识别用户要的是：

| 任务 | 默认权限与结果 |
|---|---|
| 设计 | 从意图形成新 Skill 的设计与正式产物 |
| 审阅 | 给出独立判断，不修改文件 |
| 重构 | 在用户授权范围内重新组织并修改现有 Skill |
| 迭代 | 根据真实表现定位根因，更新并重新验证 |
| 局部调整 | 只检查指定内容、直接影响及必要的平台契约，不扩展为整体重设计 |

明确的新建、重构、迭代或局部修改请求，只授权修改用户指定或已经确认的目标范围；只要求设计讨论、方案、建议或审阅时不落盘。新建前确认创建位置，并把该位置确定为唯一维护源。

确认目标 Agent 或平台、目标 Skill 的唯一维护源、已有设计材料和可用反馈。唯一维护源是未来修改应落入的权威副本；安装副本、部署副本和历史稿不自动获得这一身份。缺少的信息如果会改变定位、权限、结构或验证结论，先向用户确认，或明确采用条件性结论；不要用外部背景或自行猜测补齐。用户只要求建议时，不把建议升级为修改授权。

涉及定位、结构或行为逻辑时，读取 [治理视角](references/governance.md)。新建设计、整体审阅、重构和迭代默认还要读取 [表达与叙事](references/expression.md)。只有范围明确且局部的任务才按实际影响缩小加载与工作范围。

本目录中的 `SKILL.md`、`governance.md` 和 `expression.md` 已包含第一审的完整方法。`skill-creator` 及其自带资源是唯一外部方法依赖；用户请求、目标 Skill 和必要原始证据是任务输入；官方平台事实、校验器和隔离能力是运行条件。不要从外部治理文档、工作区规则、记忆、历史对话或其他设计 Skill 补全本方法。运行条件不可用时，准确报告对应校验或第二审未完成。

## 第一审：独立治理与表达编译

先脱离旧稿结构，依据用户当前意图、代表性用例、目标 AI 的可见上下文和平台事实，建立最小充分的能力模型：

- Skill 要帮助下游完成什么结果，不负责什么；
- 谁会触发，何时触发，输入和完成状态是什么；
- 哪些信息需要常驻、按需加载、实时取得或保持不可见；
- 哪些内容是平台事实、运行事实、用户决定、实测知识、推断或历史，以及哪份源码或资产是唯一维护源；
- 哪些行为只有说明即可，哪些需要结构、脚本、权限或验证机制保证。

再审阅现有产物。不要用旧稿的章节、流程或依赖定义问题空间，也不要为体现重新设计而制造新结构。每个保留项和新增边界都应由当前决策价值证明。

根据根因选择局部修补、结构重构或整体替换。结构性问题包括错误总模型、职责混杂、双重真值、加载错位、设计过程泄漏、权限与技术能力混淆，以及未经验证的流程被写成可执行能力；不要用追加规则压住这些问题。

内容的事实、授权、可见性和可执行性成立后，继续判断表达是否真正完成：下游能否沿清晰主线建立对象心智，标题和层级是否表达概念关系，每段是否产生判断增量，设计痕迹是否已经退出，未来内容能否自然落位。没有明显违规只达到最低门槛；如果下游仍需承担本可由作者完成的组织、拼接和推断，继续重新表达，而不是判定通过。

第一审先形成明确的设计、修改方案或审阅结论，再进入第二审。给用户的阶段性说明保持低维，只暴露当前需要裁决的关键选择，不把内部使用的全部治理视角变成固定报告栏目。

## 第二审：skill-creator

`skill-creator` 是完成双审所需的唯一外部 Skill。除它以外，不调用其他 Skill 提供设计、治理、表达或审阅框架。第一审已有具体产物、方案或审阅结论后，在新的隔离上下文中调用宿主可用的 `skill-creator` 做一次独立工程复核。它只承担通用 Skill 视角，例如：

- description 与触发边界；
- 上下文成本和渐进披露；
- 自由度是否匹配任务脆弱性；
- references、scripts、assets 的必要性和入口；
- 平台契约、静态校验、测试和迭代完整性。

向第二审提供目标产物、目标平台、代表性请求和必要的原始证据，不提供第一审结论、怀疑的问题、预期修复或评分答案。它的通用建议不自动覆盖用户已确认的意图和本 Skill 的治理判断；平台硬约束作为可行性事实处理，冲突和关键取舍交还用户。

第二审只读，不直接修改任何维护源。向隔离执行者提供目标产物的临时副本或等价只读输入，以及复核所需的原始证据；不得让它浏览原工作区、第一审记录、邻近设计材料或历史文件。第二审只使用 `skill-creator` 及其自带资源，不调用其他 Skill；它只返回带证据的工程问题和建议，由当前执行者根据用户意图收敛修改。任一隔离条件无法满足时，报告独立第二审未完成。

不设置固定第三审。`skill-creator` 或隔离的新上下文不可用时，可以应用通用工程视角，但必须明确说明独立第二审未完成，不把同一执行者的再次自检包装成完整双审结果。

局部调整仍保留双审，但两审都只检查指定内容及直接相邻契约。纯错字或不改变含义的格式修补不需要调用本 Skill；用户仍明确调用时，完成必要校验即可，不借机审查整体结构。

## 实现与验证

获得修改授权后，只修改已经确认的唯一维护源。目标环境如果把设计理由与运行 Skill 分开保存，定位、结构或行为逻辑变化时，只同步修改已经纳入授权范围的相关设计材料；不在授权范围内时报告仍需同步的位置。纯格式修补不需要制造设计记录。运行 Skill 只保留下游行动需要的定位、判断依据、入口和边界，不复制设计推导、被否定方案和历史状态。

完成两次审阅后，按当前任务权限收敛修改或审阅结论并验证：

- 运行目标平台提供的格式或结构校验；
- 检查链接、资源入口、重复正文和平台专属字段；
- 对复杂或高风险 Skill，用代表性任务做受限上下文前向测试；默认使用隔离副本或临时目录，测试执行者只看到目标 Skill、原始请求和必要原始材料，不看到第一审结论、预期缺陷或评分答案；
- 根据测试暴露的误解修正结论；已经获得相应修改授权时再修正产物，不为想象中的所有情况预建规则。

静态格式通过只证明对应平台契约有效，不等于整体审阅通过。纯审阅任务不修改目标文件；在可用材料范围内完成适用的静态检查，并把无法执行的行为测试或环境验证明确列为未完成项。

前向测试验证行为，不构成第三套设计观点。宿主无法提供隔离的新上下文时，准确说明未执行，不把设计者自检当作前向测试。测试可能接触生产、长时间运行或需要额外授权时，先取得用户同意。

## 交付

先给出当前结论和最重要的结构判断，再说明实际修改、验证证据和仍需用户裁决的问题。区分事实、推断与用户决定；没有完成第二审或关键验证时，准确报告当前成熟度。
