# Docker 部署目标路由

从当前请求、Agent 记忆或设备资料识别目标类别；Agent 已知的信息不重新询问。用户没有指定且上下文没有相反信息时，默认按 `vps_h` 部署。具体设备、端口、域名和现场服务仍读取当前事实。

目录中的 `<project>` 表示稳定的项目或 Compose 栈名。单容器项目通常与 `container_name` 相同；多服务项目使用共同项目名，不以其中一个容器随意命名整个目录。

## `vps_h`

- 项目目录：`/opt/1panel/docker/compose/<project>/`。
- `1panel-network` 是 vps_h 主要业务容器默认使用的共享集成网络，用于保持服务互联、反代衔接和后续演进的一致性；只有存在具体、可验证的项目网络模型、安全隔离或运行代价等反例时，才偏离到 Compose 默认网络或其他模式。纯栈内辅助组件可留在内部网络，是否加入按其业务边界判断。
- 不需要反代时完全忽略 OpenResty。
- 标准 HTTP 反代时，处理好 Compose 与应用侧的端口、公开 URL、TLS 终结、cookie、proxy trust 或 CORS；不在交付中提醒、解释或复述用户能通过 1Panel UI 完成的普通反代操作。
- 存在 WebSocket、SSE、流式或长请求、大文件、特殊 path、代理头、超时、CDN 影响等非标准要求时，先完成 Docker 与应用侧配置，再简洁说明用户需要在 OpenResty 中手动处理的差异。提供足够操作依据，但不默认直接修改 OpenResty。

1Panel 当前只提供项目目录与日常环境的一致性，不围绕它发明额外部署流程。

## `vps_l`

- 项目目录：`~/docker/<project>/`。
- 使用项目默认 Compose 网络；只有需要连接现场已有的其他 Docker 服务时，才接入对应网络。
- 不需要反代或公网入口时忽略 Caddy。
- 用户要求反代时，把接入已有 Caddy 作为部署的一部分：读取现场已有组织与证书配置，增加所需站点或路由，验证配置并让变更生效。不要重建证书体系；域名、配置所有权、证书引用或路径等现场事实形成阻塞时，及时与用户对齐。
- 用户只要求方案或 Compose 时，不因此修改 Caddy。

## 本地

- 项目目录：`~/docker/compose/<project>/`。
- 默认优先使用已有外部网络 `dockernet`；项目确实需要内部隔离网络时可以补充，不强行把所有服务只放在一个网络中。
- 默认无公网和反代需求，不主动引入 Caddy、OpenResty、Cloudflare 或公网域名。
- 用户明确要求局域网访问时，处理监听地址、端口和必要边界；只有进一步要求域名或反代时才扩展入口设计。

镜像、更新、组件复用、bind mount、Compose 风格和敏感信息门槛在三类目标中共用，不在本文件重复。
