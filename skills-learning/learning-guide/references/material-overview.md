# 项目或整组材料导读

适用于整个项目、代码库、课程、书籍、一组关联文档，或其他包含多个区域和层次的学习对象。

目标是让用户先看见整体怎样成立，而不是把目录换一种说法。根据对象实际具有的结构，寻找：

- 它整体面对什么问题、承担什么作用或形成什么系统；
- 哪些区域、组件或内容线构成骨架，它们如何依赖、协作或传递信息；
- 哪些是核心机制，哪些是支撑设施、实例、适配层或延伸内容；
- 从整体进入局部时，哪些关系能提供稳定的认知坐标。

对于有作者组织的材料，显化其宏观编排与问题范围；对于代码库或其他非教程对象，从入口、边界、数据或控制流、核心模块关系中重建学习视角。不要逐目录介绍，也不要把架构审计、代码评审或完整技术讲解混入导读。

对象没有天然学习顺序时，可以说明哪些部分在认知或依赖上更基础、哪些建立在其上。把这种顺序表达为面向理解的观察，而不是项目作者规定的课程路线。

让用户离开导读时获得一张有主次、有关系的整体地图，同时仍保留进入具体材料后才会展开的机制和细节。
