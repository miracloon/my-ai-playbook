# Stage 2: Concept Design

阶段2将已确认的意图转化为定位、功能、能力和工作路径相互支撑的概念模型，并在思想层面确认模型闭合。

## 推进方式

以下内容是需要覆盖的设计语义，不对应固定对话轮次。信息充分时可以合并推进；存在关键分歧时继续讨论，直到形成共同理解。

## 定位

定义 agent 的角色、用户为什么会找它，以及它在本驻地生态中的位置。

## 功能模型

从用户视角整理核心功能、功能关系、主干和必要分支，并形成 agent 自身的功能边界。功能模型服务于整体心智结构，不追求穷尽。

当用户主动需要建议或启发时，可以在用户已经声明的边界内提出合理的功能方向，帮助用户看见未想到的用途。建议只用于打开思路，不替用户扩大目标，也不默认加入设计。

## 能力模型

为核心功能建立所需能力，形成“用户目标 → 功能 → 能力”的对应关系。

| 概念 | 面向 | 要回答的问题 |
|------|------|--------------|
| 功能 | 用户视角 | agent 为用户完成什么 |
| 能力 | 技术视角 | agent 依靠什么手段做到 |

能力保持在概念层，只需支持用户建立对 agent 的完整心智模型。

## 工作路径

将定位、功能和能力组织为接到任务后的主干路径与真实分支，说明触发场景、推进逻辑和最终交付。

## 概念可行性验证

通过典型场景推演、思想实验和必要调研检查：

- 核心功能是否都有能力支撑
- 工作路径是否闭合
- 能力之间是否存在明显断点
- 用户设想的方案在概念上是否成立
- 是否存在必须修改定位或功能模型的硬阻塞

必要调研只服务于概念能否成立的判断。

## 完成标准

向用户呈现完整概念模型：定位、核心功能、所需能力、主干工作路径、关键分支和功能边界。用户认可后进入阶段3。
