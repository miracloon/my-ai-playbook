# Skill 维护

在修改 Skill 自身时，根据其 Metadata 确定事实关系和修改落点。Metadata 是供下游规则解释的维护语义，不是脱离任务场景机械执行的状态机；具体做法可以适应客户端能力，但不能改变字段表达的中心、本地或禁止修改关系。

本 Skill 不约束 Skill 的正常使用、任务输出或项目文件。

## 客户端常驻入口

在使用本治理方式的客户端中加入：

> 当准备修改某个 Skill 自身时，先检查其 `SKILL.md` frontmatter；若存在 `metadata.ry_agent_update`，加载 `ry-skill-maintain`，并由它结合字段语义、当前客户端的原生能力和用户授权完成对应维护与副本更新；不存在则按客户端默认规则处理。

## 中心与副本

- 远程中心：`https://github.com/miracloon/my-skill-repo.git`
- 本地中心工作副本：`~/workspace/ai-meta/my-skill-repo/`
- 中心目标：本地中心工作副本与目标 Skill 的 `metadata.ry_source_path` 组合后的目录
- 客户端副本：当前 Agent 实际加载和使用的 Skill 目录

远程中心保存多个 Agent 可以共同取得的发布事实；本地中心工作副本是读取、修改、验证和提交这份事实的操作界面。修改前同步远程，修改后提交并推送，两者就仍是同一个中心，而不是两个维护源。

客户端副本通过客户端自身的 Skill 管理能力安装和更新。原生命令从远程或本地取得 Skill 只影响分发方式，不改变中心事实与安装副本的关系。

## 读取维护语义

读取即将修改的 `SKILL.md` frontmatter，并检查 `metadata.ry_agent_update`：

- `source`：确认后的修改进入中心目标。
- `local`：修改只进入当前客户端副本。
- `disabled`：不修改该 Skill。
- 字段缺失：退出本 Skill 的来源治理，回到客户端默认行为。

字段值无法识别时不猜测。说明当前值和无法确定的维护关系，请用户决定。

## `source`：更新中心

目标是修正所有客户端可以共同取得的中心正文，而不是单独维护当前安装副本。

### 确认中心状态

- 解析本地中心工作副本和 `metadata.ry_source_path`，确认结果仍在仓库内、目标目录存在，且目标 `SKILL.md` 的 `name` 与当前 Skill 一致。
- 在修改前取得远程最新变化，使本地中心工作副本基于当前共享事实；不要在未知新旧关系上直接编辑或推送。
- 检查中心目标已有修改、远程变化和当前副本反馈之间的关系。涉及当前 Skill 的差异或冲突先向用户说明并完成协调，再继续编辑。
- 与当前 Skill 无关的工作保持原状，不清理、不覆盖、不纳入本次提交。它们不妨碍安全更新时继续当前任务；如果实际阻止同步或推送，显式报告阻塞，不伪装完成。

### 取得修改授权

说明要解决的问题、中心目标路径、拟议修改及影响，再取得用户对源更新的明确批准。当前请求已经明确授权本次中心修改时，不重复索要同一授权。

如果拟议变化只适用于当前客户端或环境，不要因字段是 `source` 就直接污染中心；说明适用范围，并让用户决定是否应形成客户端本地变化。

### 修改并发布

- 以中心目标的当前内容为基线应用有效修改。本地副本用于提供证据、比较或临时验证，不用于整体覆盖中心目录。
- 同步更新 `metadata.version`。版本保持带引号的三段字符串；兼容性修补通常递增末位，更大的行为变化按实际影响调整。
- 执行目标 Skill 适用的格式、链接和行为验证。错误显式暴露，不用忽略失败换取发布完成。
- 提交只包含当前 Skill 和本次修改确实需要的关联文件，不夹带仓库中的其他工作。
- 把提交推送到远程中心。只有远程中心已经包含新正文，才算完成共享源更新；仅修改本地中心工作副本不算完成。

### 刷新当前客户端

- 中心推送完成后，使用当前客户端原生的 Skill 更新命令刷新安装副本，不用文件复制另建一套同步流程。
- 更新前可以先用客户端原生命令检查新版本；更新后核对 Skill 名称、版本和必要内容已经对应中心正文。
- 告知用户中心路径、新版本、提交与推送结果，以及当前客户端是否已经刷新。其他客户端可以随后按各自节奏更新，不宣称已经自动同步。

Hermes 使用：

```bash
hermes skills check <skill_name>
hermes skills update <skill_name>
```

尚未安装时，使用中心正文的 raw URL：

```bash
hermes skills install 'https://raw.githubusercontent.com/miracloon/my-skill-repo/main/<skill_collection>/<skill_name>/SKILL.md' --yes
```

其他客户端使用各自对应的原生安装与更新命令。命令不可用或执行失败时显式报告，不以手工复制伪装为原生更新成功。

## `local`：保留客户端变化

- 中心正文只是当前副本的分发基线；修改直接发生在当前客户端的 Skill 目录。
- 默认不修改本地中心工作副本或远程中心，也不主动把这项变化作为中心更新处理。
- 本地变化存在后，不再对该 Skill 使用客户端原生更新命令，否则中心版本会覆盖本地内容；以后需要引入中心变化时先审查并合并差异。
- 除非客户端另有本地版本约定，不把中心的 `metadata.version` 改写成新的中心版本号。
- 完成后告知用户修改内容、适用原因，并明确该副本已经形成客户端本地变化。
- 用户明确要求回收本地修改时，把本地内容作为反馈，对照中心当前正文选择具有共享价值的部分，再按 `source` 流程更新、提交和推送中心；不要整体覆盖中心，也不要在中心更新后自动更新当前本地副本。

## `disabled`：保持不变

- 不修改当前客户端副本、本地中心工作副本或远程中心。
- 向用户报告发现的问题，可以提供建议，但不把建议落实为 Skill 修改。
- 只有用户明确改变这一维护决定后，才按新的语义继续。
